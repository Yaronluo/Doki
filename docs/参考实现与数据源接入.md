### 3.1 Hero 原型的时序起点

下列数值来自固定版本 HeroTimeline；REWORK-006 按最新要求采用不压黑的磨砂模式进出时序。焦点滚动和详情仍由 tvOS 公开能力实现，未运行 Android 对照录屏，不能宣称逐帧一致。

| 阶段 | 上游时长与先后 |
|---|---|
| 进入时货架弱化 | 150ms，与底色轨同时开始 |
| 底色轨进入 | 压黑时 300ms；其他情况 150ms |
| 背景内容进入 | 底色轨结束后 400ms |
| 文字进入 | 内容起步后延迟 100ms，再运行 300ms；中断恢复时可省去延迟 |
| 退出时文字与背景 | 同时收起：文字 150ms，背景 250ms |
| 退出后货架与底色恢复 | 背景收起后开始：货架 250ms，底色 350ms 或 250ms |

Doki 不把“每次焦点变化都先黑屏”作为要求。背景等待策略、旧图保持和 Hero 压黑轨分别处理；先保证条目身份和焦点稳定，再比较观感。

### 3.2 后续多平台研究（当前只实施 TV）

| 平台 | 保留的体验 | 适配方式 |
|---|---|---|
| Apple TV | 货架选择、内容连续性、详情进出与返回保持 | 系统标签导航/焦点起步；遥控器方向、确认、返回和长按分别验证 |
| iPhone | 背景和内容层次、卡片到详情的连续性、选集反馈 | 触控点击/按压触发；保留原生 TabView 与手势返回，不模拟持续遥控器焦点 |
| Mac | 同一内容视觉语言、背景切换、卡片反馈、详情连续性 | 指针悬停和键盘选择分别处理，原生侧栏与窗口自适应，不强制全屏 TV 排版 |

内容连续性与可取消交互是首版质量要求，具体布局和动效按 Doki 当前设计规范。自动预告片和额外主题仍后置；系统导航与自绘效果协调，避免重复缩放。

### 3.3 必须覆盖的动画回归

上游的 [TvNativeCardFocusHoldTest.kt](https://github.com/GrahamZen/izuko-tv/blob/9d9cba2ad0ef7e443ffa3542cee91fba345edafa/app/shared/ui-tv/src/androidDeviceTest/kotlin/ui/foundation/tv/nativeview/TvNativeCardFocusHoldTest.kt) 验证焦点返回时外观不回缩；[TvNativeHeroTitleHandoffTest.kt](https://github.com/GrahamZen/izuko-tv/blob/9d9cba2ad0ef7e443ffa3542cee91fba345edafa/app/shared/ui-tv/src/androidDeviceTest/kotlin/ui/foundation/tv/nativeview/TvNativeHeroTitleHandoffTest.kt) 验证标题在过渡层交还时恢复可见。Doki 采用相应行为作为自己的验收场景：

1. 连续切换多张卡，停止后背景、Logo/标题和操作按钮属于最后一张。
2. 图片晚到、请求失败或缺 Logo 时，不闪空、不回退到已离开的条目。
3. 动画进行一半按返回或改方向，从当前视觉状态恢复，不累加过时 completion。
4. 从详情页返回，原卡片和货架滚动位置恢复，卡片不先回缩再放大。
5. 标题交接期间不会双重显示，也不会永久消失。
6. 浅/深色、减少动态效果、减少透明度与低性能设备均有可用状态。

## 4. Animeko：采用的资源与解析语义

已核对当次 [MediaSource 文档](https://github.com/open-ani/animeko/blob/8ca97e5d54f9a97dddb1a4fb2ec89d411e1b7802/docs/contributing/code/media/media-source.md)。其关键约束包括条目级查询、浏览与自动匹配分层、稳定 mediaId、播放时再解析短期地址，以及接口凭据与视频请求头分开。

Doki 对应 `search → listEpisodes → resolve`，把稳定资源、短期解析和播放会话分离。某个源不能自动匹配不等于不能手动浏览；源返回的默认清晰度是配置提示，不直接作为播放器真实能力徽章。

订阅规则执行语义仍需按具体格式测试。本次没有运行 Animeko 引擎，也没有宣称 TypeScript 适配器已与其结果一致。

### 5.1 首版适配面

| 配置字段或行为 | 处理要求 |
|---|---|
| 外层、factoryId、version | 识别版本和未知工厂；给出可查看的兼容性状态 |
| `searchUrl`、`rawBaseUrl`、关键词配置 | 正确编码变量、处理相对地址；不将整份 JSON 作为可执行脚本 |
| `subjectFormatId`、`selectorSubjectFormat*` | 从实际启用格式选配置；CSS 与 JSONPath 各自测试 |
| `channelFormatId`、`selectorChannelFormat*` | 保留线路身份、顺序和剧集归属；格式名与配置对象按上游语义映射 |
| 季/集正则与命名捕获组 | 检查 Kotlin/Java 正则与 JS 的差异；不支持的表达式明确报告 |
| `matchVideo`、嵌套 URL 和 iframe 页面 | 有界解析，HTTP 优先、必要时浏览器；按捕获语义识别地址，禁止无限递归 |
| Cookie、Referer、User-Agent | 站点会话隔离、视频域名授权；凭据不盲目跟随跨域请求 |
| `requestInterval` | 同源请求共享节流与并发边界，交互请求优先于预热 |
| tier / channelTiers / 缺省值 | 已提供则保留，缺省则使用明确回退；配置排序与真实健康度分别维护 |
| 清晰度、语言等默认配置 | 作为候选提示，实播探测后再确认 |

CSS 选择器可能依赖原解析器的扩展语义，不能保证浏览器 `querySelector` 原样可用。相对地址、空字段和缺省对象也要进入 fixture，不能只对一个成功样本做字符串转换。

### 5.2 无源 ID 的更新规则

1. 首次导入为条目分配内部 providerId，保存订阅来源、初始 origin、名称、配置摘要和身份线索。
2. 新快照用已有注册信息匹配原条目；普通规则修复只更新 revision，不改变 providerId。
3. 名称/域名/模板大改、重复候选或匹配不唯一时标记待确认，不按数组下标或名称强行继承。
4. 临时 CDN 域名不参与稳定身份；配置全文摘要用于版本，不作为永久 providerId。
5. 保留用户启停、选线、映射和健康记录；订阅更新不静默覆盖人工修正。

### 5.3 导入与启用步骤

```text
指定仓库固定版本
  → 拉取并保存来源 / 版本 / 原始摘要
  → 结构解码与兼容性检查
  → 内部稳定身份注册 / 更新差异
  → 显示规则及 disabled / 待验证状态
  → 筛选 1～2 个候选源
  → fixture 回放与真实搜索 / 解析 / relay / seek 验证
  → TV 实际播放验收
  → 标记当前环境可用，再逐步扩展
```

不读取 `dist/all.json` 或 `dist/bt.json`。更新不在未验证时替换正在播放会话的请求上下文；已验证快照可回滚。导入成功、搜索成功、解析成功与实际可播放分别记状态。
