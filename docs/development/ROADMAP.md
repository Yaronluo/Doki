# 开发任务与依赖

> 当前只实施 tvOS 客户端与必要 Hub；iPhone/Mac 客户端全部后置，不创建 target/UI 或跨端验收门槛。第一批已执行；APP-001/HUB-001 有本地 verified 证据，UI-001 为模拟器 implemented_unverified，SRC-001/PLAY-001 仅有单源技术验证且受内容安全阻断，META-001 的匿名 Bangumi 读取与可选 TMDB 横幅已有实现；本轮已实现无 token 横幅与网页登录/配对，横幅有实际 TV 画面；真实账号和完整集成仍未验收。真实状态以 [CURRENT_STATE](../handoff/CURRENT_STATE.md) 为准。

## 状态定义

- `not_started`：尚无实现。
- `in_progress`：实现进行中，列出剩余事项。
- `implemented_unverified`：有实现但未满足验收，不能当作可用交付。
- `verified`：达到任务条件且有可复查证据。
- `blocked`：明确外部前提阻止该任务，写出所需输入；其他独立任务继续。

## 开发批次

### 第一个批次：可构建的 TV 原型

1. 完成 ENV-001 的可本机调查部分，列出需要用户补充的设备/Hub 信息。
2. 创建 APP-001 的真实工程源与最小共享包，记录实际 tvOS scheme。
3. UI-001 先做发现、追番、详情、原生导航/玻璃和播放器壳；随后补日历、搜索、我的、设置。
4. 建立 HUB-001 配置/契约骨架和自造 fixture；密钥空值返回 notConfigured。
5. tvOS 构建/启动与遥控器导航证据交接；真机未运行时明确记录，不要求 iPhone/Mac 产物。

第一批已执行；工程、TV 原型、Hub 骨架和单源技术链路的实际结果见 CURRENT_STATE/WORK_LOG。无需先获取全部 API 凭据才能继续 UI/契约工作。

### 第二个批次：真实播放与账号

SRC-001 → PLAY-001；AUTH-001 与可独立的契约工作穿插完成。真实 TV 完整集、seek、重开续播是扩源前门槛。任何源站失败先定位阶段，不能一口气扩展几十个规则掩盖问题。

### 第三个批次：个人内容、同步与弹幕

SYNC-001、META-001、DAN-001/002 → DAN-003。保留 Doki 原生设计，不以重现上游页面收尾；将映射修正、同步问题与弹幕设置做成真实可操作入口。

### 第四个批次：恢复、部署与交付

SRC-002、OPS-001 → QA-001。录屏验证 TV 返回、焦点和弹幕时钟；真实演练断网、过期、设备撤销和备份恢复。按照实际目标设备安装应用，不能只交 DerivedData 路径。

## 排期方法

v0.3 的工期区间已因设计方向与弹幕范围变化失效。先完成 APP-001/HUB-001/PLAY-001 的基线测量，再依据工作量和用户设备/凭据条件排期；当前不给未验证的完整交付日期。
