# 架构与产品决策记录

> 当前有效基线：[v0.4 · TV 首发修订](../Doki-设计方案-v0.4.md)。ADR-009 已收敛平台范围；早期决策的三端实现/验收部分仅为历史，其余架构选择仍按适用范围执行。

## ADR-001 · Apple 原生设计为主

状态：已确定，2026-10-29。

用户明确要求“参考，不是照搬”，需要 iOS 样式和 Liquid Glass。Doki 独立设计内容层级，iPhone 原生 TabView/NavigationStack、Mac 原生侧栏/窗口、tvOS 原生标签/焦点。izuko-tv 的状态协调与内容连续性仅作机制参考；Android 页面、尺寸和动画时序不成为验收目标。

影响：[APPLE_NATIVE_UI](../design/APPLE_NATIVE_UI.md) 是 UI 细节依据，旧概念图和 v0.3 的“主要视觉目标”表述失效。最初规划为三端分别验收，现被 ADR-009 收敛为仅 TV。

## ADR-002 · 真实 Liquid Glass 与清晰内容层

状态：已确定，2026-10-29。

系统组件优先，必要自定义控制层用公开玻璃 API，正文、海报、章节不全部玻璃化。玻璃不靠 blur/图片仿造；系统已提供的材质不重复叠加。辅助功能设置必须有可读呈现。

影响：设计、组件实现和帧率证据一起验收；不能用 HTML 静态效果图证明原生材质。

## ADR-003 · 家庭 Hub（早期三端范围已由 ADR-009 取代）

状态：实施基线，网络与设备假设待实测。

客户端负责原生交互、播放、本地检查点和弹幕渲染。Hub 负责凭据、元数据、映射、解析、媒体 relay 与跨端权威状态。tvOS 无需网页 JS 运行时。首版按单用户多设备、LAN/已有 WireGuard 访问规划。

影响：账号、Ubuntu 硬件和路由仍需调查；Hub 故障应保留缓存和本地操作。不得把不受控源站放进家庭内网访问边界。

## ADR-004 · 指定在线订阅，有限验证

状态：已确定。

优先适配 MajoSissi/animeko-source 的 online.json。首批只验证/启用 1～2 个源；无统一上游 ID 时维护内部注册表，更新可回滚。BT/磁力/做种不在范围。

影响：订阅解析成功与真实播放分开报告；稳定资源、短期地址和播放会话分层；原始凭据不进客户端。

## ADR-005 · 显式映射与有版本的观看状态

状态：已确定。

Bangumi 章节为身份基准；TMDB、源站和弹幕库分别映射。进度按有效会话 epoch/事件序号更新，主动回看允许位置变小。手动已看意图优先，outbox 按实体/字段组串行且带 revision。

影响：并发事务、旧回调、旧重试和跨端冲突必须有测试；人工映射不能被后台任务覆盖。上游无条件写入的并发边界需明确。

## ADR-006 · 弹弹play旁路弹幕

状态：已确定纳入首版；真实凭据与额度待配置。

使用弹弹play开放弹幕网络，由 Hub 鉴权取数/缓存，客户端按媒体时间调度。先支持读取、修正、设置和偏移；发送后置。弹幕失败不阻塞视频。

影响：新增 DokiDanmaku、独立章节映射和按资源剪辑存储的偏移；必须验证 seek/倍速/暂停/字幕区域。PiP/AirPlay 维持视频/原生字幕，自绘弹幕不承诺跟随，不引入烧录。

## ADR-007 · 生成工程、模块化单体与契约

状态：已确定方向；2026-10-30 已建立 XcodeGen tvOS 工程、Swift 包和 Server 骨架，部署仍未建立。

XcodeGen 管工程，多 app target + 共享包；API/Worker 来自一个 TypeScript 项目，用 Postgres 持久状态、Redis/BullMQ 临时任务，Caddy 反向代理。运行版本在环境任务中锁定，避免凭空写入未验证版本。

影响：先建立真实构建命令和配置 schema，再在文档中宣布可运行；接口生成前内部契约仍为草案。

## ADR-008 · 状态与证据驱动交接

状态：已确定。

设计资料已完成不等于应用实现；fixture、编译、真实 API、模拟器和真机证据分开。每批工作更新状态、证据和下一步。缺少凭据可先实现与测试旁路，但相关首版功能仍保留，不能默默删除。

影响：[CURRENT_STATE](../handoff/CURRENT_STATE.md) 只记录真实现状；[ROADMAP](../development/ROADMAP.md) 记录依赖和完成条件。

## ADR-009 · 首版仅 TV，其他客户端后置

状态：已确定，2026-10-29；来自用户最新明确指示。

当前只开发 tvOS 客户端和必要 Hub，不创建 iPhone/Mac target、页面、专属适配或测试门槛。平台中立模型/协议可自然保留扩展能力，不为未来平台建设过量抽象。Mac 作为开发主机不构成 Mac 客户端交付。

配对和 Bangumi OAuth 改由 Hub 轻量网页 + 普通手机/电脑浏览器辅助完成；不要求另一 Doki App。TV 原生风格、真实 Liquid Glass、指定在线源和弹弹play弹幕仍在首版。

影响：取代 ADR-001/003/006/007 中的“三端首版”执行范围，以及相应构建/验收要求；其他关于原生设计、Hub、会话、同步、弹幕和秘密隔离的原则继续有效。已同步 AGENTS、主方案、设计、任务、接口、环境、验收、当前状态和交接提示词。

## ADR-010 · 真实源只进入开发预览，内容安全阻断产品启用

状态：accepted，2026-10-30。

问题：需要一个真实 animeko-source 规则完成搜索、解析、Hub relay、seek 和退出续播技术验证；但验证源（樱花动漫）真实视频流中含第三方赌博广告，且当前没有内容授权结论。

决定：

1. 只把 `yinghua` 作为开发 provider 接入；`POST /v1/dev/source-preview` 和签名 `/s/...` relay 仅在 `NODE_ENV != production` 注册；TV 入口标为开发，不进入普通源启用列表。
2. Hub 执行源站请求、规则解析和 relay；TV 只拿短期签名 URL，不接触上游 Cookie/URL。session 在内存、有 TTL，重启即失效。
3. 本机 198.18.0.0/15 透明代理只在本地显式设置 `OUTBOUND_ALLOW_BENCHMARK_NETWORK=1` 时放行；生产禁止该开关。真正 IP 固定/强制代理仍待 OPS-001。
4. 内容安全发现写入交接：该源不得默认启用、公开部署或作为内容交付；含广告/受版权画面的截图与原始媒体已删除。技术链路通过不等于来源可用。

影响：SRC-001/PLAY-001 保持 `implemented_unverified`（技术链路有模拟器证据），产品启用被内容安全阻断；正式 PlaybackSession/epoch、AUTH/SYNC/DAN 继续后置。下一批必须先决定可接受授权的源，或保持该 adapter 仅开发/禁用。

## ADR-011 · 公开元数据先接通，竖版封面与横幅分工

状态：accepted，2026-10-30，用户要求大改原型并尽可能接入真实数据。

问题：原型把竖版封面填入横向卡片，TMDB 仅有空配置，自造内容与演示源占据正常使用路径；账号依赖不应阻止免登录公开资料。

决定：正常启动读取真实 Bangumi；没有 Hub 时平台中立 CatalogClient 只请求官方公开 API，有 Hub 时由 Hub 读取。公开目录和账号能力分离，不因此关闭完整 META/AUTH 任务。账号/弹幕缺凭据可暂缓并说明申请位置，不能伪造成功。

普通条目始终竖版海报；TMDB 仅作独立横幅增强，保守区分 TV/movie、标题与年份，歧义需手动选取；手动修正暂存本机并优先于自动匹配。无横幅时保留竖图，不裁剪冒充。先独立实现 izuko 的稳定内容/可取消预览机制，再用系统 matched transition 与 glass 控件表达 Apple 交互；不复制上游代码/素材/时序。

影响：DokiCore CatalogClient / DokiUI / tvOS / Hub metadata、Zod/OpenAPI、设计规范、接口与配置文档。真实源含广告的 ADR-010 继续有效；本轮不新增源、不部署、不创建其他客户端。无迁移或依赖版本变动。生产 egress IP 固定/鉴权仍按 OPS/AUTH 后续验收。

## ADR-012 · 顶部原生标签与全宽横幅，无密钥优先接入

状态：accepted，2026-10-30；来自用户最新明确指示。

用户要求参考 izuko 的界面层级，同时保留 Apple 系统元素，指定顶部标签、去侧栏、横幅铺满顶部。采用原生 TabView + 根层真实 backdrop，独立 SwiftUI 海报墙/详情与公开玻璃操作；取代 ADR-011 的局部横幅表现，不改变竖版封面和独立背景图分工。

账号改为 Hub 邮箱/密码/验证码网页登录并自动生成个人令牌，优先于原 OAuth 规划；不要求 Client ID/Secret。密码/Cookie 不保存，令牌 AES-GCM 加密，设备 Keychain；只读导入账号追番，写回/完整同步/上游撤销后续实施。新增迁移 0002 管理网页会话与配对设备名称。

图片先在线读取公开 bangumi-tmdb-map，命中时直接使用 TMDB CDN，不要求 token；缺图补查和搜索修正才使用可选 token。表/图片使用条件分别记录，不打包参考仓库素材。弹弹play按用户要求暂缓，未删除后续要求或冒称审核已提交。

影响：tvOS/DokiUI/DokiCore、Hub auth/metadata、Zod/OpenAPI、配置与验收。真实账号、真机、可用视频源、完整同步和生产部署仍待验证；不扩大历史单源播放结论。

## ADR-013 · 收起式深色磨砂导航与独立热门轮播

状态：accepted，2026-10-30，用户最新两轮截图要求及明确视觉纠正。

取代 ADR-012 的顶部标签及自定义玻璃视觉：左上角显示头像，侧栏采用低调的深色系统 Material 和白色圆角焦点条。移除自定义 `glassEffect`、glass 按钮及玻璃容器，操作用平面实色控件；保留原生 NavigationStack、焦点、搜索和 AVKit。减少动态效果/透明度分别回退；不把参考图作素材打包。

五个目的地保留独立导航状态；边缘上/左呼出，右侧离开及下方离开收起。菜单内上下选择仍可用；详情/播放不响应根侧栏呼出。菜单动画可中断，不等待网络。

热门独立于本季评分推荐：Bangumi `POST /v0/search/subjects` 空关键词、`sort=heat`、动画/非 NSFW，经 Hub `GET /v1/popular` 或无 Hub 官方直读。热度表示收藏人数，不声称实时在看榜；最多六部每八秒切换，手动可前后选择。导航/详情/播放/后台/滚离横幅时暂停，减少动态效果与 VoiceOver 下不自动切换。刷新失败保留旧内容，提供重试；旧目录快照可向后解码。

影响：tvOS/DokiUI/DokiCore、Hub metadata/OpenAPI、UI 与协议测试、设计/验收/交接；无迁移、依赖版本或播放源变更。实际账号头像和 TV 真机仍需独立验收，不扩大既有播放结论。

## ADR-014 · 彩色磨砂与单一按钮焦点层

状态：accepted，2026-10-30，用户最新三图纠正。

ADR-013 实现中的近黑横幅渐变先被磨砂，导致普通背景过暗；侧栏强制暗色 Material 与短圆角也无法体现用户图二的通透度。改为蓝灰基底 + 原始内容图扩散 + 轻系统材质；发现页滚离横幅后复用磨砂背景。导航采用更通透的 Material、420pt 宽/44pt 圆角、白色胶囊焦点条；侧栏采用公开 UIVisualEffectView/UIBlurEffect 和暂停的 UIViewPropertyAnimator 控制轻模糊强度，保留背景轮廓；不用降低整片磨砂 opacity 的方式混入清晰文字。按用户随后圈图纠正：磨砂只在侧栏面板内，右侧内容与横幅始终清晰，不因菜单出现全屏模糊/遮挡。减少透明度时使用蓝灰实体底色。

图三的按钮问题来自自绘填充外又使用 tvOS PlainButtonStyle 的系统焦点底板。对筛选、日期、设置行、弹幕选项、源选择和重试统一使用自有样式与公开 focusEffectDisabled，保留焦点移动/动作，只绘制一套反馈。系统输入、Picker、确认面板与 AVKit 仍保持原生；普通按钮不重新使用 glassEffect。

影响仅 tvOS/DokiUI、UI 专项测试与设计/验收/交接；无 API、依赖、数据库或源变更。截图与模拟器交互不代替真机性能/完整辅助功能验收。


## ADR-015 · 货架内预览与账号胶囊原位展开

日期：2026-10-30。依据：用户最新五图与接替暂停对话的明确指示。

发现页热门轮播与当前货架预览分开。首次选择海报在原货架上方展开预览，再次选择进入原生详情；不替换热门横幅或把用户送回首页顶端。预览状态、焦点和条目身份分别保存，晚到图片不能改变热门选择。首次选择不需要等待图片或详情请求。首页仅保留“立即播放”，无可用产品源时明确反馈；不以演示视频代替真实条目。

导航保留 ADR-014 的通透磨砂与焦点条，但从带头像/昵称的胶囊原位展开为面板，双向使用同一可中断尺寸动画；内容下移后允许隐藏胶囊，边缘呼出机制不依赖其可见性。未登录不显示继续观看，冗余操作教学与目录计数从普通浏览画面移除。只影响 tvOS 与 DokiUI；没有新增 Hub 接口、平台、依赖或迁移。


## ADR-016 · 持续磨砂与货架 Hero 行为对齐

日期：2026-10-30。状态：accepted，用户最新四图覆盖 ADR-014/015 的条件式背景和独立时序取舍。

磨砂底层持续存在，右上清晰横幅用羽化遮罩覆盖其上，不由菜单展开状态关闭渐变或材质。Hero 文字独立于滚动货架固定在屏幕上方，当前行停在下方，上方行/卡片番名随独立轨道淡出；Hero 内焦点移动更新预览，再次确认详情，返回保留 Hero。使用固定 izuko 版本的无压黑时序，独立实现可中断线性采样轨道；tvOS ScrollView/焦点/详情转场继续公开原生能力，未承诺 Android 逐帧一致。整个页面去磨砂对焦不符合本轮持续磨砂要求，因此不启用。

首页/货架复用标题 Logo 组件；海报下方只保留番名。仅 tvOS/DokiUI 与专项验收受影响，无 Hub、依赖、接口或迁移变化。


## ADR-017 · 真正模糊的背景与统一货架焦点导航

日期：2026-10-30。状态：accepted，来自用户追加两图纠正。

REWORK-006 以全屏清晰图羽化混合磨砂，实际文字区仍可见锐利轮廓；改为完整高斯底图与局限右上的清晰横幅，移除洗灰材质叠层，缺横幅时海报仅用于模糊底色。蓝灰基底与 screen 混合避免普通背景压成近黑；减少透明度保留实色回退。

货架共享一个展开占位，保持身份、父层双向弹簧改变高度，位置、文字与图片分别协调，避免瞬间插入 460pt 后再滚动。发现页容器统一处理方向命令，按行与列维护显式焦点目的地；向上切行先恢复该行可见，避免 opacity=0 的旧行无法接受原生焦点。展开期间按内容坐标减去共享占位高度滚动，避免移动锚点把整张卡片送出屏幕。回首页采用 ScrollPosition 的绝对顶部位置与 tvOS 原生 focusScope/resetFocus，头部可见后更新播放按钮的焦点身份，交接期间旧卡片暂不获取焦点。整卡焦点显式放大到 1.15；匹配转场来源移入缩放层，避免源边界裁剪放大效果。仅影响 tvOS/DokiUI 和对应验收，无 Hub、依赖、协议或迁移变化。
