# Doki：Apple 原生界面与系统材质

> 当前设计基线，随 [v0.4](../Doki-设计方案-v0.4.md) 生效。当前首版只做 tvOS 完整界面，iPhone/Mac 客户端不实施也不验收。

## 1. 设计立场

Doki 是一款围绕“今天看什么、上次看到哪、这一集是否看过”的个人追番工具。界面由观看任务组织，内容封面提供个性，Apple 系统组件提供熟悉的操作方式。

借鉴 izuko-tv 的内容连续性、旧图保持、可中断动画和返回位置记忆；重新设计导航、布局、信息密度和材质。验收目标是“像成熟的 Apple 原生应用”，不是与参考截图相似。

Doki 的三个具体取舍：

1. **热门与续播分层**：用户指定首屏为 Bangumi 热门轮播，下面保留继续观看与本季推荐。热门按收藏热度，不把评分排名称为热度。
2. **观看记录清楚**：追番列表区分今日更新、正在看、已完成；进度、收藏和弹幕属于各自清楚的操作入口。
3. **内容稳定，控件轻盈**：正文和海报保持实体可读，导航用低调系统磨砂材质，操作用平面控件；背景不跟随每一次无意悬停剧烈切换。

## 2. TV 首版导航与页面

采用左上角头像与可收起的透色磨砂侧栏：**发现 / 追番 / 日历 / 搜索 / 我的**，为每个内容区保留焦点和滚动位置。需要设置时进入原生面板；不保留顶部标签栏，不把 iPhone 底部栏搬上电视。

| 页面 | 内容顺序 | 遥控器与焦点要求 |
|---|---|---|
| 发现 | Bangumi 热门轮播 → 继续观看 → 本季推荐 → 今日放送 | 首次默认落到有意义内容，横向货架可上下切换；返回恢复原卡片 |
| 追番 | 状态筛选 → 我的条目和下一集 | 筛选后稳定落点；已看/未看/正在播放状态清楚 |
| 日历 | 日期选择 → 对应放送条目 | 方向键切日与列表，返回不丢日期；计划放送与实际可播分开 |
| 搜索 | 系统搜索输入 → 结果分组 | 使用系统输入能力，错误/无结果可恢复，结果按稳定 ID 进入详情 |
| 我的/设置 | Hub 连接/授权 → 源 → 弹幕 → 关于 | 电视可查看状态与管理偏好；首次 owner/授权用浏览器辅助，不开发手机 App |
| 详情/选集 | 顶部全宽横幅/标题 Logo、评分/日期、播放/收藏、章节、简介 | 主操作清楚，剧集可选、源与弹幕匹配可修正；缺图不挡操作 |
| 播放 | 系统 AVPlayerViewController + 必要弹幕绘制层 | 播放/暂停/seek、字幕/音轨、选集、换源、弹幕设置均可用遥控器操作 |

继续观看采用横向内容块，普通条目采用竖版海报；不强行统一图片比例。热门最多轮播六部；导航展开、进入详情/播放、页面不活跃或横幅离开视口时暂停。减少动态效果/VoiceOver 时只手动切换。实际可播更新与计划放送分开；只有年月日的数据保留 date-only。

页面焦点以稳定条目/章节 ID 管理，异步加载和分页追加不抢焦点。缺图保留布局和文字，刷新保留旧内容直到新内容成功。大屏字体、可见行数和间距由真机观看距离验证，不按 Android dp/sp 固定换算。

## 3. 当前平台边界

| 角色 | 首版工作 |
|---|---|
| Apple TV / tvOS | 唯一客户端目标：完整页面、播放器、弹幕、遥控器与焦点、安装验收 |
| Doki Hub | API/解析/relay/状态/凭据，以及配对与 OAuth 所需的轻量网页 |
| 普通手机/电脑浏览器 | 用户打开 Hub 网页辅助设置和授权；不是 Doki iPhone/Mac App |
| Mac 开发主机 | Xcode 构建/模拟器/工具，不能因此增加 macOS app target |
| 后续 iPhone/Mac 客户端 | 当前不创建 target、页面、适配层或测试门槛；只保留自然的平台中立模型/协议 |

## 4. 材质与控件契约（2026-10-30 用户纠正）

用户最新截图要求覆盖先前强制 Liquid Glass 的决定。自定义界面移除 `glassEffect`、GlassEffectContainer 和 glass 按钮；普通操作不添加透镜或重复焦点底板；导航按最新图二使用大圆角与胶囊焦点条。系统 AVKit、搜索输入和系统面板保留公开原生行为。

| 部位 | 当前决定 |
|---|---|
| 收起式导航 | 半透明轻磨砂 Material（保留背景轮廓），420pt 侧栏、44pt 圆角、白色胶囊焦点条；头像/昵称/时间在顶部 |
| 普通背景 | 蓝灰底与内容色扩散，去掉压黑渐变；发现/详情顶部保留清晰横幅，发现页滚到货架时转磨砂 |
| 操作按钮 | 平面实色、短圆角；自绘控件使用自有 ButtonStyle + focusEffectDisabled，单一焦点形状，不叠系统 `.plain` 焦点底板 |
| 筛选与提示 | 低对比实体底色，不叠玻璃 |
| 海报、正文、章节、弹幕 | 以内容可读性为主，不套材质 |
| 减少透明度 | 实色侧栏与背景，保留相同布局和操作 |

向上/向左到内容边缘可呼出导航；向右离开侧栏收起，向下离开菜单底部也收起。侧栏内上下仍用于选择目的地；头像可直接选择打开。菜单出现时内容不可获得焦点，收起后恢复原内容；详情/播放器中的方向操作不被根导航抢走。

## 5. 设计 token 与组件职责

以下是 Doki 的初始产品值，实施后按设备调整；不能把上游 Android dp/sp 乘二作为规格。

| 语义 | 初始规则 |
|---|---|
| 背景/表面 | 系统语义颜色，跟随浅/深色；禁止固定灰色遮罩覆盖所有页面 |
| 字体 | tvOS 系统文本样式与远距离层级；长标题可换行，辅助功能设置保持可读 |
| 主色 | 默认使用系统 tint，海报颜色承担内容个性；不自动染色所有控件 |
| 间距 | 以 4/8/12/16/24/32pt 为基础阶梯，按平台/内容变化 |
| 圆角 | 系统组件沿用系统形状；内容卡约 12～20pt 起步，非统一大胶囊 |
| 焦点目标 | 遥控器选择区域明确，聚焦放大不被裁切，不靠颜色单独提示 |
| 可读宽度 | TV 简介不铺满整屏，章节行和网格利用安全区域 |

建议组件职责：`PosterCard` 只画内容与选择态，`ContinueWatchingRow` 表达集名/续播/进度，`EpisodeRow` 分开已看与正在播放状态，`PlaybackOptionsSheet` 管理源/字幕/音轨/弹幕入口，`ConnectionStatusView` 只展示需要用户处理的连接问题。

页面没有明显故障时，不显示“命中缓存”“加载旧快照”等实现文案。读取旧内容立即可见，刷新成功平滑替换；必要的日期、来源、失败和重试保留。

## 6. Doki 自己的动效语言

原则：**输入立即反馈，内容连续，操作可取消**。系统转场承担导航，少量自定义动效补充内容关系；上游时序仅用于理解多段动画的协调问题。

| 行为 | Doki 方案 | 初始自定义预算 |
|---|---|---|
| 按压/选择 | 系统按钮反馈，必要时轻微缩放 | 约 100～160ms，不叠两次按压效果 |
| 页面进入/手势返回 | NavigationStack 等原生交互转场 | 系统控制，不强制定时导航 |
| 首页内容刷新 | 稳定身份、旧图保持、内容淡入 | 约 180～260ms |
| 详情图片连接 | 符合平台能力时使用系统匹配/zoom；不适合时正常 push | 不等待高清图或服务端请求完成 |
| 精选内容切换 | 用户选择后切换局部背景/标题，不全屏压黑 | 约 200～300ms，未选中目标不能晚到覆盖 |
| TV 焦点 | 以系统焦点为主，轻量抬升或标签强调 | 真机调校，恢复焦点时保持外观 |
| 导航展开/收起 | 短距离移动和淡入，可中断弹簧过渡 | 减少动态效果时直接更新 |

以上不是性能承诺。减少动态效果时切换为短淡入/直接更新；减少透明度和高对比度时保留系统可读性。动画状态按稳定条目 ID 与 generation 管理，取消旧请求/旧 completion。

不采用“按下后等整套背景变清晰再导航”的硬门槛。匹配转场的目标图不可用时，显示正常详情并异步补图。连续返回、快速切集和晚到图片都必须正确。

## 7. 弹幕与 iOS 控件风格

弹幕开关位于播放器可发现的菜单/操作入口，展开为原生 sheet/Form：开关、密度、字号、透明度、显示区域、时间偏移、重新选择弹幕库。主屏不堆多排圆钮或覆盖底部字幕。

首次使用弹幕默认关闭，用户开启后记住设备偏好；每一集的匹配与每一源的时间偏移分别保存。配置和网络失败在设置面板给出准确状态，不打断正常视频。TV 所有设置均可通过遥控器完成，原生播放控制不被弹幕面板抢走焦点。

## 8. 页面交付与设计验收

### 8.1 历史实现（2026-10-30，REWORK-001；由 REWORK-003 取代）

正常启动改为真实 Bangumi。普通番剧、搜索和日历统一竖版海报；局部预览和详情横幅仅使用独立背景图，TMDB 未配置时保持原比例海报。首页保留稳定身份，轻量焦点放大/按压与延后预览协调；导航使用原生 matched source / zoom，减少动态效果时关闭自定义缩放转场。返回原卡片在真实网络模拟器测试中通过。

控制层改为系统 `.glass` 按钮，玻璃与焦点由同一个控件管理，不手工给按钮外套另一个 interactive 玻璃；减少透明度时切回普通系统按钮/实色。内容不整片玻璃化。图片流读取/缩图不占主线程，保留成功图直到新图可用，同 URL 请求复用。海报固定标题区域，避免长短标题让同排封面上下错位。

浅/深色、真实海报、搜索、日历、详情与减少动态效果/透明度分支的模拟器截图位于 `.local/artifacts/REWORK-001/final-screens/`；导航录屏为同目录上级 `tvos-navigation.mp4`。Debug flags 只验证对应 UI 分支，不替代系统辅助功能或真机遥控器/帧率验收。TMDB 无真实 token，因此横幅的 live 画面未验收。fixture 仅在显式 `--demo-fixtures` 时用于测试，不再作为正常浏览资料。


1. 当前只为 TV 交付发现、追番、日历、搜索、我的/设置、详情/选集、播放器；示例数据清楚标注。
2. 每端至少检查浅/深色、长标题、缺图、空列表、网络失败、待同步和弹幕失败。
3. TV 检查焦点边缘、快速按键、远距离可读性、安全区域与系统辅助功能；iPhone/Mac 不作为本期门槛。
4. 提供截图判断层级、平面控件与磨砂导航，提供录屏判断中断、返回和图片替换。概念 HTML/PNG 不作为原生材质或真机性能证据。
5. 设计变更记录在 [DECISIONS](../architecture/DECISIONS.md)，可验证状态写入 [CURRENT_STATE](../handoff/CURRENT_STATE.md)。

## 2026-10-30 · REWORK-004 当前视觉纠正

用户再次提供三图：蓝灰色与彩色晕染的磨砂背景、通透的大圆角导航与胶囊选中条、禁止焦点双层白色底板。背景先扩散原始内容色，不再把带近黑渐变的横幅拿去磨砂；导航展开时仅侧栏自身使用磨砂材质；右侧横幅、文字、海报保持清晰，不施加全屏 blur、蒙层或遮挡。侧栏内混合轻磨砂与原始背景，避免完全磨成不透明色块。导航布局和普通操作控件分工，不重新给普通按钮套 Liquid Glass。筛选、日期、设置行、弹幕选项和源选择统一去掉 `.plain` 系统焦点底板；焦点状态下检查实际尺寸与截图，不能只验未聚焦状态。
